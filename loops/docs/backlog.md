# The live backlog

For anyone who reads or writes the backlog: the user, orchestrators, planning and backlog sessions, and loops (notes only).

## Deciding what's next

The backlog session (`{{prd}} plan` with no topic, in the main checkout) asks first and collects after, so a fresh one stays small: one line on the open asks (`{{prd}} asks --short`), then one multi-select poll of what the session is for (catch up, write a PRD from the backlog, decide what to run next, or triage a new issue or idea). Only then does it load its rules (`{{prd}} prompt backlog --guide`) and ingest, list and check what the picks need; catch up prints the overview (the backlog, the orchestrators, what it triaged or left for review). While the dispatcher runs, deciding what runs next is moving and holding rows (`{{backlog}} prd move`, `hold` with `why=`; `{{backlog}} prd archive` moves done rows out), and it prints no start commands. Later questions follow only from the picks; it never asks about a task the user didn't pick, and does routine chores without polling. Its proposals weigh the PRD table's dependencies and hot files and the cap of four running at once. To plan a topic it asks first: a planner in a new terminal (the user runs `{{prd}} plan <topic> --open`; an agent never runs `--open` from its own shell, where the planner would run inside the command) or planning inline in this session (`{{prd}} plan <topic>`, in its worktree). It never starts a PRD run from its own shell (`{{prd}} start`, `{{prd}} queue`): it prints the commands as options for the user to run. On "hand off" it asks nothing: any brief (its call; the user's instructions go under _Directives_, which the next session does before any poll) goes to the path `{{prd}} rotate --self --brief-path` prints, then `{{prd}} rotate --self [--brief <file>]`. Each fresh main session (start, hand-off, rotate, reopen) draws a new admiral from the machine's flavor pack (`flavor` in the machine config; `none` turns it off) and shows `backlog (<project>) · Admiral <Name>` as its Remote Control name and tab title; its record stays `backlog` and every other session reads `<name> (<project>)` with its own rank, so agents find it by `backlog (<project>)` in ListAgents. Past the soft context limit (160k) it tells the user its size at the next pause and asks: hand off or keep going (never unasked; no answer keeps going). When the user wants another backlog session for a task, it writes a brief and runs `{{prd}} session request backlog <name> --brief <file>`; the dispatcher opens `backlog - <name>` and leaves a notice (`{{prd}} session requests` lists them). Orchestrators check in with it (SendMessage) on choices that reach past their topic: it answers from the whole stack, and passes on to the user what is theirs to decide. **Bye:** a message of just 'bye' runs `{{prd}} bye` after its own checks: what it filed or triaged told to the user, no brief or session request half done.
