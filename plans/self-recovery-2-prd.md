## Problem

A topic can land and still look unfinished. When the orchestrator commits its "landed" status after the final landing, `rm` keeps the branch and never marks the row done, so the dispatcher starts the topic again and again. When it runs `rm` from inside its own worktree, the next step (`pnpm prd end`) is refused, so the session stays open. And `end` can kill a stale pid while the live session keeps running. The planner-3 incident (2026-11-25) hit all three and blocked the one lane for five hours until someone ran `rm` by hand.

A session whose resume after a usage limit is held by a dead landing journal waits forever with one log line per tick that no one reads. And nothing says what a PRD or a slice cost in tokens.

## Solution

A topic that landed is finished, whatever is left around it. The dispatcher never starts it again, and a cleanup step lands its leftover docs, removes its worktree, marks it done, ends its sessions and files one report. `rm` ends its caller itself, and `end` ends the right process. A dead landing journal that holds a resume reaches the user as one report. `pnpm prd cost` shows tokens by model for each PRD and slice, kept after the transcripts are gone.

## User stories

1. As the user, I want a landed topic marked done even when its orchestrator committed after the landing, so that the dispatcher never starts it again. (B-431)
2. As the dispatcher, I want to know from git and the plan that a topic is finished, so that I never start or reopen it whatever its row says. (B-431)
3. As an orchestrator or planner, I want `pnpm prd rm` of my own worktree to end my session, so that finishing never leaves me open with a deleted working directory. (B-812)
4. As the user, I want `pnpm prd end <name>` to end the session that's really running, and never an unrelated process, so that a reopened session doesn't outlive the end. (B-810)
5. As the user, I want a finished topic left half-done (worktree or slot held, row not done, idle or duplicate sessions, a docs-only tail) cleaned up by itself, with one report, so that it never holds a lane. (B-811)
6. As the user, I want a finished topic whose tail has code reported and never removed, so that unmerged work is never lost. (B-811)
7. As the user, I want one report when a dead landing journal holds a session's resume, naming the `land --resume` to run, so that a limit doesn't silently cost a whole session. (B-789)
8. As the user, I want `pnpm prd cost` to show tokens by model for each PRD and each slice, from session and subagent transcripts, so that I can see what work costs. (B-560)
9. As the user, I want the cost record to survive a topic's removal, transcript cleanup and `--continue`, with nothing counted twice, so that the numbers stay right. (B-560)

## Implementation decisions

- **The finish decision** (a new pure module): facts in (the topic's branch tip, the merges in dev that took it, the plan's slices left, the tail's files since the last landing merge, the registry row, the worktree and slot, the topic's live sessions with their last transcript write, the time); out: `running` (not landed, or slices left), `finished` with what's left (`tail: none | docs | code`, `worktree`, `slot`, `row`, `sessions`, `extra sessions`), or `clean`. A docs tail is one whose every file is under the plans or docs folders. It is the one place that says a topic is finished, used by `rm`, the pick and the cleanup.
- **`rm`** marks a `prd/` topic done when the finish decision says finished, a docs tail included (the branch is kept, and `rm` says the tail is unlanded). Run from inside the worktree it removes, it ends that worktree's recorded session last, after all its output, through `end`'s own check.
- **The pick** treats a finished topic like `done`: never started, planned or reopened. Its leftover worktree is the cleanup's.
- **`end`'s check** (in the session records module): a pid is the session's only while it is a live claude whose working directory is the session's worktree (the main checkout for a backlog, recovery or inbox session's recorded directory). Otherwise `end` looks for the live claude processes in that directory and ends those, saying so, and never kills the recorded pid. A session start rewrites the record's pid, so a reopen under the same name owns it. The same module lists every live claude in a worktree, for the cleanup.
- **The cleanup** (`pnpm prd finish <topic> [--dry-run] [--json]`, and a step in the dispatcher's tick for each finished topic with something left, one topic a tick, never while paused or draining): waits while any session of the topic is busy (a transcript write in the last `CARETOOK_FINISH_IDLE_MIN`, 10, minutes) or a landing journal exists for its branch. Then, in order: a docs tail goes through `pnpm prd pr` and `pnpm prd land` (a Markdown-only diff, so no Codex verdict and no tier gate); `rm` (which marks done); each remaining live session of the topic is ended; one report (topic `finish`) says what it did. A code tail, or any failed step, stops there with one report per topic and tip, keeping everything. Tidy's ask list names finished topics with something left when the dispatcher isn't running.
- **The journal report** (the resume step): when a claim waits on a landing journal whose pid is dead, the dispatcher files one report naming the session, the branch and `pnpm prd land --resume <branch>`, recorded in the claim so it's filed once per journal. A journal with a live pid stays a waits line.
- **The cost record** (a new pure module and `pnpm prd cost [<topic>] [--json]`): reads the transcripts of the topic's worktrees (`<topic>`, `plan-<topic>`, and slice worktrees when they have their own), the subagent transcripts beside each session, and the ledger. Each assistant message counts once, by message id, across every file. A subagent's tokens go to the slice its `.meta.json` description names (`<topic> slice <n>`), else the slice worktree its first prompt names, else the topic's orchestration line. A planner's go to planning. The output: per topic and per slice, tokens by model (input, output, cache read, cache write), and the total. `rm` writes the ledger for its topic (a failure prints a line and never fails `rm`); `cost` merges it with what is still on disk. Malformed lines are counted and skipped.

## Testing decisions

Unit tests for each pure decision with fictional fixtures: the finish decision (landed or not, slices left, each tail kind, idle and busy sessions, several sessions, a journal), `end`'s pid check, the journal report's once-only rule, the cost parser (dedupe across files and `--continue`, streamed repeats, subagent attribution by description, by prompt and neither, malformed lines, the ledger merge). Script-level tests with stubs and temp directories, following `tidy-cli.test.mjs` and `resume.test.mjs`: `rm` on a landed topic with a docs tail marks done and keeps the branch; `rm` from inside its worktree ends its recorded session; `end` never kills a pid that isn't the session's; the cleanup lands a docs tail, removes and reports, and keeps a code tail. No test touches the real session records, asks, transcripts or `~/.claude`. No app code changes, so no component or browser checks.
