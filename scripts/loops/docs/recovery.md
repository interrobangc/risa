# Recovery

For the recovery agent, and anyone bringing the machine back: what `pnpm prd down` and `pnpm prd recover` do. A resumed orchestrator then follows `prd doc orchestrator Recovery`.

- **The watchdog** (`watchdog.mjs`, `decide` pure; `pnpm prd watchdog [--dry-run [--json]]`) runs `recover --unattended` after a reboot past a down record, a stale dispatcher lock or kept intent, or a dead unended `prd`/`plan` record newer than the last good recover and its own first run (so closing a hand-opened tab counts as a crash, once). Stay-down, a running recover, paused, a down record with no reboot since, or a limited reading (the drain's own `readDrain`/`probeAllowed`) each mean nothing. Failures back off 10, 20, then 30 minutes with one report per incident; 75 is neither. State `.loops/.watchdog.json`; it prints only when its decision changes and always exits 0.
- **Resume after a limit** (`resume.mjs`, pure; the dispatcher's step after the drain): once a stall's reset has passed and usage is `normal`, it claims each stalled managed `prd`/`plan` session (`.dispatch.json` `resume.claimed`, then `clearStalled`), ends a live one, and reopens a dead one with `open-session.sh --carry-on` (the carry-on prompt: `land --resume`, reconcile, carry on), oldest first, one per tick, never counted as a reopen. It waits while paused, draining, on hold, rotating, in a `pnpm prd` command, or with any landing journal (even a dead one: run `land --resume`). A hand-opened session's mark is reported once and cleared.
- **The inventory** (`inventory.mjs`, pure; facts from `inventory-facts.mjs`) alone classifies worktrees (`prd`, `plan`, `active`, `merged`, `stackless`) and orders the actions; it also reports `migrating`, `dispatcher.intent`, `recover` and `landings`. Stale means the holder is gone (a slot with no worktree, the dispatcher's lock with its pid gone, the backlog lock after 30 s); live locks are never touched.
- **The recovery agent** (main checkout, `prompt.sh recover`) messages each live `prd-`/`plan-` session to carry on, reopens the rest with `pnpm prd open <target>` (`--continue` on a saved conversation, else the resume prompt, plus `--auto` when _Status_ records run-through; an iTerm2 tab, or the printed command), reports and ends. While the dispatcher runs (`dispatcher.running` in `recover --dry-run --json`) it leaves `managed` sessions to it. It changes nothing. Slice worktrees are refused: their orchestrator respawns them. A record marked `rotating` (a rotation cut short) reopens fresh with the resume prompt, never `--continue`. The agent's own session is recorded as `recover` (kind `recovery`) and, like a backlog session, reopens fresh in the main checkout.
- **Bye:** a message of just 'bye' runs `pnpm prd bye` after the agent's own check: its report table is sent.
